## 3. 画面構成
### 3.1 タイトル
- 「おくすり発明ラボ」、サブ「薬剤耐性菌にも作用する新薬を設計しよう」。
- 3行の導入: 「あなたは創薬研究チームのリーダーです。限られた研究開発費で4つの性能を設計し、100人の患者を対象としたシミュレーションで新薬を評価します。既存薬を強くするのではなく、薬剤耐性菌にも作用する新しい薬を設計することが目標です。」
- ボタン「設計をはじめる」、リンク「このゲームの科学的背景」（§6 のカード）、「遊び方」。所要時間の目安「1回 約3分」。

### 3.2 設計画面
- 上部固定: 研究開発費バー「使用 X / 90 pt」（10 pt 単位のセグメント、残りが足りない段は 🔒 とその理由を表示）。
- 各パラメータカード（折りたたみ可、初期は「意味」と5段ボタンを表示し「詳しく」で展開）:
  - 名称・現在レベル「レベル 3 / 5」・必要費用
  - 意味（1文）
  - 上げると: メリット / デメリット（各1〜2行）
  - 主に影響する結果（タグ表示）
  - 現レベルの内部値（小さく）: 例「EC50 = 1.5（低いほど少ない濃度で効く）」「耐性による必要濃度の倍率 F = 3 倍」「半減期 6.5 時間」「副作用係数 ×0.62」
- 文面（`src/config/game.ts` に集約）:
  - pot 意味「既存の抗菌薬が効く薬剤感受性菌に対して、新薬そのものがどれだけ強く作用するか。投与量ではなく、分子としての効力を表します。」 メリット「感受性菌を少ない濃度で抑えられる。耐性菌への作用が十分なときは、耐性菌にも効きやすくなる。」 デメリット「研究開発費が増える。副作用がわずかに増える。耐性菌への作用が低いままでは、耐性菌にはほとんど効かない。」 影響: 感受性菌数・回復患者数
  - mech 意味「耐性菌が持つ耐性機構（薬の分解・排出・標的の変化など）を回避する、新しい作用機序の研究度合い。耐性菌に効かせるのに必要な濃度の倍率を下げます。」 メリット「耐性菌の増殖を抑えやすくなる。」 デメリット「研究開発費が増える。副作用がわずかに増える。感受性菌への効果が低いと、耐性菌が減ったぶん感受性菌が増えることがある。」 影響: 耐性菌数・回復患者数
  - dur 意味「1回の投与で薬の濃度が保たれる時間（半減期）。」 メリット「細菌の増殖を上回る時間が長くなる。」 デメリット「研究開発費が増える。体への負担が大きくなり、副作用による中断が増える。」 影響: 両方の細菌数・副作用
  - gentle 意味「副作用を抑える設計（標的以外への作用を減らすなど）。」 メリット「副作用で治療を続けられない患者が減る。」 デメリット「研究開発費が増える。細菌を減らす効果そのものは変わらない。」 影響: 副作用・回復患者数
- 「新薬を完成させる」→ 名前ダイアログ（自動生成名は大人向け: 例「AMR-3415」形式＋カタカナ名候補「レジスタミン」等、最大16文字、個人名を入れない注意）。

## 4. 因果関係の可視化（最重要）
### 4.1 新薬の性能分析
純粋関数 `analyzeDesign(design)` を `src/game/analysis.ts` に実装し、Vitest でテストする。各パラメータ p について（他は固定）:
- `minus1`: p を1段下げた設計の結果（p=1 のときは null）
- `baseline`: p をレベル1にした設計の結果（p=1 のときは null）
- 差分: 回復数、感受性菌最終数（倍率）、耐性菌最終数（倍率）、副作用中断数、研究開発費
- 機序の指標（`src/model` の公開関数 `conc`/`killRates` から計算。モデル式は変更しない）:
  - `timeAboveS` = 0〜72h（dt グリッド）で kS(t) > gS となる時間の割合（%）
  - `timeAboveR` = 同 kR(t) > gR の割合
  - `se`（副作用指数）
- 表示（パラメータごとのカード、テンプレ文＋数値）:
  - 例 mech: 「薬剤耐性菌への作用：レベル4。耐性による必要濃度の倍率が 3 倍 → 1.6 倍に下がり、薬が耐性菌の増殖を上回る時間が 0% → 41% に増えました。その結果、耐性菌の最終数は 約1,200個 → 約103個、回復患者は 72人 → 99人。研究開発費は +10 pt。」
  - 数値はすべて analyze の値から埋める。差が 0 のときは「この条件では結果に差は出ませんでした（理由: …）」— 理由はルールで: 回復数が同じかつ細菌数差が小さい→「他の性能が律速しています」等。
  - **競合の解放の注記**: mech を上げて感受性菌最終数が 2 倍以上に増えた場合「耐性菌が減ったことで、感受性菌が増殖できる余地が生まれました（競合の解放）。感受性菌への効果も必要です。」
  - 副作用中断が増えた場合はその人数をデメリットとして明記。
- 「特に効果が大きかったパラメータ」= baseline からの回復数増加が最大のもの（同点は細菌数の変化量）。強調表示。
- 「研究開発費の内訳」= 各パラメータの費用の積み上げ横棒。

### 4.2 パラメータ比較
- パラメータ選択（4つのセグメントボタン）×方向（「1段階下げる」「1段階上げる」。範囲外は無効。上げた結果が予算超過なら比較は可能だが「参考：予算外の設計」と明示）。初期表示は「特に効果が大きかったパラメータを1段階下げる」。
- 対象パラメータだけを変更し、他は固定（コード上でも保証しテストする）。
- 表: 比較項目 × 「比較設定（レベルn）」「現在の設定（レベルm）」「差」
  - 回復した患者数 / 感染が残存 / 副作用で中断 / 感受性菌の最終数 / 耐性菌の最終数 / 感受性菌・耐性菌の減少率 / 薬が増殖を上回る時間（感受性菌・耐性菌）/ 研究開発費
- 計算は `runDesign` を使い、結果をメモ化（同じ設計を二度計算しない）。重い計算は UI をブロックしないよう `setTimeout` 分割または Web Worker（1設計 ≈ 30ms 程度）。

### 4.3 グラフ
- 横軸 経過時間（0〜72 h、24h ごとに目盛り）、縦軸 細菌数（対数、1〜10億、目盛り 1, 100, 1万, 100万, 1億, 10億）。軸ラベル付き。
- 系列: 感受性菌（緑・実線）、耐性菌（青・実線＋丸マーカー 12h ごと）。比較設定は同色の**破線**（感受性菌 = 長い破線、耐性菌 = 点線＋マーカー）。凡例は線種見本付きでグラフ外に表示。
- 「比較を重ねて表示」トグル（④で選んだ比較設定を使用）。
- オプション: 「一時的耐性状態も表示」トグル（Rq を細い灰色線）。
- 値はすべて trace（S+Sq, R+Rq, Rq）そのもの。ホバー／タップで時刻と値を表示（任意）。
- グラフ下の読み解き（ルールベース、2〜3文、実数値入り）: 例「感受性菌は最初の 6 時間で 1億 → 約30万個 に減少しました。耐性菌は 12 時間ごとの投与のたびに減少し、72 時間後に 約103個 残りました。残った耐性菌の 9割以上は一時的耐性状態にあります。」（比率は Rq/(R+Rq) から計算）

## 6. 科学的な解説（カード、各3〜4文）
1. 薬剤耐性とは: 特定の抗菌薬が効きにくくなった細菌の性質。すべての薬が効かないわけではない。
2. なぜ投与量を増やすだけではだめか: 耐性機構は必要な濃度を何倍にも引き上げることがあり、安全に投与できる濃度では届かない場合がある。本ゲームでは投与量は全設計で同じ。新しい作用機序が必要になる理由。
3. なぜ薬剤耐性菌は生き残るのか: 一時的耐性状態（遺伝的耐性とは別）と有限の観察期間。残存はモデルの予測であり、最低数を後から設定するゲーム上の制約はない。時間がたてば活動状態に戻り薬が作用する。
4. 細菌が残っていても回復するのはなぜか: 免疫が少数の細菌を排除できるという仮定。
5. 耐性菌が減っても耐性は消えない: 残った耐性菌は耐性を持ったまま。適正使用の重要性。
6. 性能と費用のバランス: 予算制約、副作用とのトレードオフ、競合の解放の例。
7. このモデルの限界: 数値は教育用の仮定・調整値で、実際の臨床成績の予測ではない（`docs/v2-parameter-model-map.md` §4 の要約）。iGEM Waseda の活動である旨の一文。
