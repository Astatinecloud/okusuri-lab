# 実装指示書（Claude Code → Codex）

小学生（特に1〜4年生）向け Web ゲーム「おくすり発明ラボ」を、このフォルダ `okusuri-lab/` に実装してください。早稲田祭で実際に公開する完成版です。

## 技術
- Vite + React 18 + TypeScript、素の CSS（CSS Modules か1枚の CSS）。グラフは **自前の SVG**（ライブラリ不要、軽量化）。
- QRコード: `qrcode-generator`（小さい、依存なし）。画像保存: `<canvas>` に自前描画 → PNG（html2canvas は使わない）。
- テスト: Vitest。
- `vite.config.ts` は `base: './'`（どの静的ホストでも動く）。ルーティングは使わず、画面は state で切替。共有URLは `#` ハッシュ。
- フォント: Google Fonts「M PLUS Rounded 1c」（weight 500/700/800）、失敗時は system-ui。

## 1. 数理モデル（最重要・UIから完全分離）
`docs/model-spec.md` が仕様。`src/config/params.json` がパラメータ（Python 参照実装 `model-ref/model.py` と共通）。

- `src/model/` に純粋関数で実装（DOM・React に依存しない）:
  - `patients(params)` → 100人の {immune, log10R0, seTol}。正規分位点 Φ⁻¹ は二分法（`model.py` の `norm_ppf` と同じ: [-10,10] を80回二分、`0.5*(1+erf(x/√2))`）。JS に erf はないので高精度近似（例: Abramowitz–Stegun 7.1.26 では精度不足の恐れ→ W. J. Cody 有理近似か、erfc の連分数など 1e-12 程度の精度のもの）を実装すること。golden の patients 配列と 1e-9 以内で一致を確認。
  - `simulate(design, params, patient)` → RK4（dt = params.dt）、各ステップ後に max(0,·)。1時間ごとの記録 {t,S,Sq,R,Rq} を返す（golden の trace と同形式: t=0..72 の73点）。
  - `conc(t, durLevel)`、`killRates`、`sideEffect`、`cost`、`runDesign(design)` → {recovered, cured, seDrop, se, representative: {trace, normEnd, resEnd, resTolEnd, actEnd, normStart, resStart}}。
  - 回復判定は model-spec の §3 通り（活動状態 S+R < cureThreshold かつ se < seTol）。
- **golden テスト**: `src/model/__tests__/golden.json`（Python 出力）の全 15 ケースで recovered・cured・seDrop は完全一致、normEnd・resEnd・trace は相対誤差 1e-6 以内。
- 科学ルールのテスト（`docs/model-spec.md` と下記）:
  - A: 強さ5・しくみ1 → 代表患者の通常菌は 99% 以上減少、耐性菌は減らない（終了時 ≥ 開始時）。
  - E: 強さ5・しくみ1・時間5 でも耐性菌は減らない。強さ1→5 に上げても しくみ1 では耐性菌の終了時数の減少は 10 倍未満（全 dur で）。
  - B: 強さ1・しくみ5 → 耐性菌は 99% 以上減少。
  - C: 強さ5・しくみ5 → 両方 99.9% 以上減少。コストは8で他の性能に1コインしか残らない。
  - D: しくみ5・時間5 → 耐性菌 99.9% 以上減少、しかし終了時 > 10 個（完全消滅しない）。
  - 全 435 の予算内設計で: 全状態が非負・有限、recovered ∈ [0,100] の整数、代表患者の耐性菌終了時 ≥ 10、同一入力で同一出力。
  - dt を 0.025 に変えても全設計で recovered の差が ≤ 2（重ければ代表的な30設計で可）。
  - しくみレベルを上げると（他固定）代表患者の耐性菌終了時数は単調非増加。
  - 予算 9 を超える設計は `canAfford` が false。
- 計算は `runDesign` 1回で 101 本の ODE（100患者+代表）。ブラウザで 100ms 程度以内を目標（メインスレッドで可。重ければ Web Worker）。

## 2. 画面（すべて日本語。漢字は小学2〜3年生まで＋ふりがなは使わず、ひらがな中心）
画面は縦長スマホ（360×640）〜PC まで。タップ領域 ≥ 48px。1画面の情報を絞る。明るいパステル（クリーム背景 #FFF8EC、ミント、ピーチ、ラベンダー）、角丸 20px 以上、やわらかい影。かわいく日本の教育ゲーム風、アメリカンなカートゥーン調は避ける。アニメーションは CSS / SVG。`prefers-reduced-motion` で控えめに。

### 画面1 タイトル
- 「おくすり発明ラボ」（発明はそのまま）、サブ「きみだけの薬で100人を助けよう！」
- 説明「きみは今日からおくすり研究者！」「薬のつよさやしくみを工夫して、たくさんの人を元気にしよう！」
- ふわふわ動くフラスコ・カプセル・ばい菌キャラの SVG アニメ。大きな「はじめる」ボタン。
- 小さく「あそびかた」「ばい菌と薬のおはなし」（§5 の科学説明をカードで）ボタン。

### 画面2 薬の開発
- 上部に常時: 「けんきゅうコイン 🪙 のこり X / 9」をコインのアイコン9枚で表示（使用済みは色が抜ける）。
- 4つの性能カード（アイコン＋名前＋1行説明＋**5段階のボタン**（スライダーより小学生が押しやすいため。丸い段ボタン 1〜5、選択済みまで色が塗られる。＋/−ボタンも併設））:
  1. 💪「ふつうのばい菌への強さ」— 「ふつうのばい菌をへらす力だよ！ 薬の量をふやすのではなく、薬そのものの力をみがくよ。」
  2. 🔑「つよいばい菌にきく新しいしくみ」（狭い画面では「新しいしくみ」）— 「薬がききにくいばい菌にも、きくように工夫しよう！」。ⓘで「つよいばい菌は、薬をこわしたり外に出したりして、薬からみをまもっているよ。新しいしくみの薬は、そのまもりをくぐりぬけられるんだ。」
  3. ⏰「薬がはたらく時間」— 「薬がどのくらい長くはたらくかを決めよう！ 長いほど体への負担もふえるよ。」
  4. 💚「体へのやさしさ」— 「体にやさしい薬をめざそう！」
- 段を上げるには1段1コイン。コインが足りない段は押せない見た目（グレー＋🔒）にし、押すと「コインがたりないよ！ ほかの性能を下げるとつかえるよ」とコイン表示を揺らす。下げると返金。
- 初期値は全部1（コイン9のこり）。全部1のままでも完成可能。
- 「薬を完成させる！」大ボタン。押すと薬の名前を決める小ダイアログ: 自動生成名（例: 性能に応じた語の組合せ「ピカピカ・キラリン」「まもりやぶり・スッキリン」など）＋「ほかの名前」ボタン＋自由入力（最大10文字、「じぶんの名前は入れないでね」と注意）。決定→画面3。

### 画面3 シミュレーション（約 12〜15 秒、スキップ可「けっかを見る」）
- 上: 「代表の患者さんの体の中」パネル。ばい菌キャラが動き回る。
  - 通常菌: 丸い黄緑のにこにこ。
  - 耐性菌: **同じ大きさ・同じ顔**の紫色で、うすい「バリア（まもりのまく）」を身につけている。強いモンスターにはしない。説明ラベル「薬がききにくいばい菌（つよいわけじゃなくて、薬がききにくいだけ）」。
  - q状態の菌: 少し透明・眠っている顔（zzz）で、画面すみの「かくれが（薬がとどきにくいところ）」にいる。
  - 薬のつぶ（カプセル型の小さな粒）が濃度 C(t) に応じた数で漂う。通常菌に当たるとポンと消える演出。耐性菌には、しくみレベルが低いとバリアではね返される（「キン！」の小さなエフェクト）、しくみが高いとバリアをくぐりぬけて効く（鍵のマークが光る）。
  - 画面上のキャラ数は代表患者の個数の **対数** に比例（例: 1億個 ≈ 24匹、1万個 ≈ 12匹…）。「画面のばい菌1ぴきは、本当はたくさんのばい菌をあらわしているよ」と注記。終了時に 1 匹以上表示されるのはモデル値が ≥ 10 個あるため（ゼロ表示しない根拠はモデル）。
- 下: 細菌数グラフ（SVG、横軸「じかん（日）」0〜3日、縦軸 log10 目盛ラベルは「1億」「100万」「1万」「100」「1」）。線: ふつうのばい菌（S+Sq、黄緑）、つよいばい菌（R+Rq、紫）。時間とともに左から描かれていく（アニメの時刻と同期）。描画値は `runDesign` の trace そのもの（グラフと内部計算の一致）。
- 「1日目」「2日目」… の進行表示と、ひとことナレーション。

### 画面4 結果
- 大きく「100人中、XX人が元気になった！」＋100人の人アイコン（元気=にこにこカラー、まだ治らない=グレー、薬が体に合わなかった=ブルーの絆創膏）。凡例付き。
- 研究者ランク（★と名前）。基準を「ランクのきまり」で表示:
  - 95人以上 ★★★★★「でんせつの おくすり博士」
  - 80〜94 ★★★★「スーパー博士」
  - 60〜79 ★★★「おくすり博士」
  - 30〜59 ★★「研究員」
  - 0〜29 ★「見ならい研究員」
  - 追加バッジ: 80人以上かつコインをのこした →「せつやく名人」バッジ。
- 「ふつうのばい菌」「つよいばい菌」それぞれ: はじめ → おわり の数（約◯個、万・億表記）、「◯分の1にへった！」または「◯倍にふえちゃった…」、小さく減少割合 %（小数2桁、99.99% 等）。耐性菌が残っているときは必ず:
  「でも、薬がとどきにくいところに、まだ少しのこっているみたい。」
- 使ったコイン X/9、4性能のレベル（小さなバー）、薬の名前。
- 結果コメント（2〜3文、ルールベース。下記 §3）。
- ボタン: 「けっかを保存する」「もう一度つくる」（画面2へ。前回の設定を残す。「さいしょから」も可）。

### 画面5 結果の保存
- canvas で 1080×1350 の結果カード画像を生成（タイトル、薬の名前、4性能、回復人数、ランク、コメント、QRコード、「教育用の簡単なモデルです」注記）。
- 「画像をダウンロード」（`a[download]`）。iOS Safari 等では画像を表示して「長押しで保存してね」。可能なら Web Share API（ファイル共有）も。
- 共有URL: `location.origin+pathname#r=<pot><mech><dur><gentle>&n=<encodeURIComponent(name)>`。このURLを開くと再計算して結果画面を直接表示（入力は検証: 各1〜5、予算内、名前は10文字以内に切り詰め、HTMLとして挿入しない）。QRコードをその場に大きく表示。
- 個人情報は収集しない。サーバー不要。localStorage は使っても前回設定の記憶程度（try/catch）。

## 3. 結果コメントのルール（優先順に2〜3個選ぶ）
- しくみ ≤ 2 かつ 耐性菌が増えた/ほぼ減らない: 「ふつうのばい菌はへったけど、薬がききにくいばい菌がのこっちゃった！」「つぎは、新しいしくみを研究してみよう！」
- 強さ ≤ 2 かつ 通常菌が十分減らない（代表患者の S+R ≥ 1e4）: 「つよいばい菌にはきいたけど、ふつうのばい菌がまだ多いね。」「ふつうのばい菌への強さも大切だよ。」
- seDrop ≥ 30: 「薬が体に合わなかった人が多かったみたい。」「体へのやさしさや、はたらく時間を見なおしてみよう！」
- 作用時間1で cured < 80: 「薬がはやくきれちゃったかも。はたらく時間をのばしてみよう！」
- やさしさ ≥ 4: 「体にやさしい薬をつくれたね！」
- 通常菌 99.9% 以上減少: 「ふつうのばい菌をたくさんへらせたね！」
- 耐性菌 99% 以上減少: 「新しいしくみで、つよいばい菌もたくさんへったよ！」
- 回復 ≥ 95: 「すばらしい！ いろいろな性能をうまく組み合わせたね！」
- 最後に（95未満のとき）「もっとよい薬をつくるには、どんな工夫ができるかな？」

## 4. 構成
```
src/config/params.json     # モデルパラメータ（変更しやすい）
src/config/game.ts         # 予算・ラベル・ランク基準・コメント文言
src/model/*.ts             # 純粋関数のモデル + __tests__
src/ui/...                 # 画面コンポーネント
src/share/...              # URL エンコード/デコード、canvas 画像、QR
```
- `npm run build` で `dist/` に静的サイト。`npm test` で全テスト。
- ブラウザ更新でエラーにならない（ハッシュがあれば結果画面、なければタイトル）。
- `public/_headers` は不要。`index.html` に `lang="ja"`、viewport、OGP title/description、favicon（SVG フラスコ）。

## 5. 科学説明カード（「ばい菌と薬のおはなし」と結果画面の「もっと知りたい」）
- 薬剤耐性とは:「ある薬がききにくくなる、ばい菌の性質のことだよ。」
- なぜ新しい薬が必要?:「薬がききにくいばい菌には、新しいしくみの薬が役立つことがあるよ。」
- なぜ耐性菌が残る?:「薬がとどきにくい場所や、薬がききにくい状態のばい菌が、まだのこっていることがあるよ。でも、時間がたつと目をさまして、薬がきくようになるものもいるよ。」
- なぜ強いだけではだめ?:「薬のつよさだけでなく、どんなしくみでばい菌にきくかが大切なんだ。」
- なぜ副作用を考える?:「薬は病気をなおすためのものだけど、体への負担も考えることが大切なんだ。」
- 菌がのこっても治る?:「体には、のこった少しのばい菌をやっつける『守る力（めんえき）』があるよ。」
- おうちの方へ（小さい字）: 「このゲームは科学を学ぶための簡単なモデルです。実際の薬の開発や治療を正確に再現したものではありません。薬は決められた量・回数を守って使いましょう。たくさん飲んでも薬がききにくいばい菌に効くようにはなりません。」
